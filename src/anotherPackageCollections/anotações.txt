A principal diferença entre essas duas linhas está em como o Java organiza os dados na memória do computador, o que afeta diretamente a velocidade do seu código [1, 2].
Aqui estão os pontos principais:
1. Estrutura Interna
ArrayList: Funciona como um vetor (array) dinâmico [1, 3]. Os elementos ficam lado a lado na memória. Se a lista cresce demais, o Java cria um novo array maior e copia tudo para lá [1, 2].
LinkedList: Funciona como uma lista duplamente ligada [1, 4]. Cada elemento (nó) guarda o seu valor e um "ponteiro" para o próximo e para o anterior [1, 5]. Eles ficam espalhados na memória [5]. 
2. Performance (Onde cada uma brilha)


Operação 									ArrayList										LinkedList
Acessar por índice (ex: get(50))			Muito rápido. Ele sabe exatamente onde o item está [1, 6].	Lento. Ele precisa percorrer do início até chegar no item [1, 4].
Inserir/Remover no final	Rápido (na maioria das vezes) [1, 3].	Rápido [1].
Inserir/Remover no meio	Lento. Ele precisa "empurrar" todos os itens seguintes para o lado [1, 4].	Rápido. Ele apenas muda os ponteiros dos vizinhos [1, 5].



1. Quando usar ArrayList (O "Padrão Indústria")
Acesso frequente: Se você precisa fazer buscas pelo índice (lista.get(i)) ou iterar (fazer um for) sobre os dados.
Economia de memória: Ocupa muito menos espaço que a LinkedList.
Cache do Processador: Como os dados estão em endereços contíguos na memória, o processador consegue ler os dados muito mais rápido (devido à locality of reference).
Uso Profissional: É a escolha em 95% dos casos em APIs REST, processamento de listas de usuários, bancos de dados e interfaces.
2. Quando usar LinkedList (O "Caso Especial")
Fila ou Pilha (Queue/Deque): Ela é excelente para ser usada como uma fila (first-in, first-out), pois inserir e remover nas pontas é muito eficiente.
Inserções/Remoções constantes no início: Se o seu sistema precisa remover o primeiro elemento o tempo todo. No ArrayList, isso obrigaria o Java a "empurrar" todos os outros milhares de itens uma casa para trás.
Uso Profissional: Algoritmos complexos de manipulação de nós ou quando você está implementando buffers de mensagens onde o processamento ocorre sempre na cabeça da lista.
Por que a ArrayList quase sempre vence?
Mesmo que a LinkedList pareça melhor para "inserir no meio", na prática, para inserir no meio você primeiro precisa encontrar o lugar. Como a LinkedList é lenta para encontrar posições, o tempo que ela perde procurando o índice anula a vantagem de inserir o nó rapidamente.
Dica de código limpo (Clean Code):
Sempre que possível, declare sua lista usando a interface List. Isso permite trocar a implementação depois sem quebrar o resto do código:


List<Integer> minhaLista = new ArrayList<>(); // Fácil de trocar por LinkedList se precisar
